## Scope ruling — doors unchanged, no disposable-repo rehearsal

The three conditions in [drills/README.md](README.md#doors-unchanged) hold at
this candidate head, and each was measured here rather than copied from an
earlier record or from the authorizing issue (#233).

`0.6.0`, and the measurement over the release path is:

```
$ git diff --numstat 0.6.0 -- <release-path>
1	1	.github/workflows/release.yml

$ git diff -U0 0.6.0 -- <release-path> | grep -E '^[-+]' | grep -vE '^(\+\+\+|---)'

+  CEREMONY_SELF_REF: "0.6.2"

One file, one line, and that line is the `CEREMONY_SELF_REF` pin the condition
exempts by name. No door logic, no decide table, no facts gathering, no
changelog extractor and no `bin/` script differs from the last rehearsed tag.

Measured against `main` at `750acd6` — before this PR's own stamp — the same
diff is one file and one line as well, `-  CEREMONY_SELF_REF: "0.6.0"` against
`+  CEREMONY_SELF_REF: "0.6.1"`: still the pin alone, this time the one the
`0.6.1` cut stamped. It is not empty here as it was in
[drills/0.6.1.md](0.6.1.md), and the reason is only that the baseline is two
releases back rather than one. Two intervening pin stamps are still one pin

The same pin is stamped in `labels.yml` and `labels-sweep.yml` in this PR —
`self-ref-check.sh` requires every workflow to name one release, and reds the
tree otherwise. Neither file is on the release path, so neither enters the
measurement above; they are named here so the candidate's full diff and this
record cannot be read as disagreeing.

**2. The release path came from the script, not from transcription.**

```

**3. The baseline is the last rehearsed tag, and it qualifies.**
[drills/0.6.0.md](0.6.0.md) is a **full rehearsal** — its own scope ruling
reads "a full rehearsal is owed, and doors-unchanged is refused", and all six
of its probes ran. The `0.6.0` release is published
(`2026-08-05T09:35:51Z`), and `main` was re-armed afterwards: `8c3a4d1` wrote
`0.6.1-dev` at `2026-08-05T09:35:51Z`.

The anchor is `0.6.0` and not `0.6.1` because the baseline is the last
*rehearsed* tag rather than merely the previous one: [drills/0.6.1.md](0.6.1.md)
is itself a doors-unchanged record, so it cannot anchor another. That is the
rule working as written — nothing here chains one doors-unchanged assertion
off another, and the accumulated release-path delta from the genuine anchor is
still only the pin.

**A waiver was considered and is the weaker record.** `WAIVED` is a
maintainer's judgement under the standing paragraph; `doors unchanged` is a
mechanically checked claim the panel can re-run from this file. Where the
conditions hold, the checkable shape is the one owed — the narrower shape is
not a substitute for a rehearsal or a waiver, but it is not optional in favour
of them either.
